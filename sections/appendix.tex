\subsection{Evaluation-guided repair}
\label{sec:res-loop}
Iterative CQ generation in Exp2 grew the CQ set from 12.0 to 85.8 per shard and evidence recall from .093 to .377 (Table~\ref{tab:glance}). Evaluation-chosen patches scored 1.9 points above random patches ([$-$1.6, 5.3]). Exp5 repaired queries first and patched only graph-side failures, gating each patch on reserved curation CQs and never on held-out questions; evaluation-chosen patches again did not improve on random patches ($-$0.3; upper bound 3.1, margin 5).

\subsection{Exp8 arms and measures}
\label{app:exp8def}
The reference arm uses 40 CQs at the 1$\times$ token budget. For each shard the budget comes from a reference run, and an arm stops after using 95\% of it. Other arms are named by CQ count and budget: 160 CQs at 1$\times$, 160 CQs at 4$\times$ and 40 CQs at 4$\times$. The source check is on in the 40-CQ and 160-CQ arms. Each generated CQ is embedded with Qwen3-Embedding-0.6B and compared with the top 5 retrieved chunks, and a CQ that fails is regenerated up to 3 times.

In Exp8, KG-only QA gives the answerer graph facts only. Measure F2 takes the vector answer unless it abstains, and then the KG-only answer.

\subsection{Registration records and run details}
\label{app:registration}
\paragraph{Plans and labels.}
Each experiment has a plan, fixed before the main run, that states hypotheses and decision rules, and a deviation log that we kept during the run. The list comparisons in Exp7 are descriptive intervals, and G$-$L0 in Exp4 and Exp5 (Table~\ref{tab:arms}) is a post hoc secondary contrast. Seeded extraction (U-ext+vocab) is an arm added after an internal review and run under its own addendum. The comparison of iText2KG with the Exp7 arms was registered, and its outputs are descriptive; the comparisons with EDC and AutoSchemaKG were registered as descriptive, except EDC with the list (registered, Holm-corrected). Decisions use the labels of each plan: \emph{improved}, \emph{not improved} and \emph{not established}. An interval that includes zero is reported as \emph{did not separate}. The plan for the chunk-retrieval comparison registered answer correctness as the measure.

\paragraph{Checks added after the main study.}
Eight checks added after the main study each had a plan fixed before its run: the synonym list, fact precision, vector versus hybrid QA, the Exp7 arms on T-REx, the subsets at equal fact count, the induced list, the list induced outside the evaluation shards and the share of the list given. A further check compares chunk retrieval with the graph. The synonym-list check replaces the 22 names by synonym phrases; its hypotheses are registered and its vocabulary-adoption measure is post hoc. Its comparison arms are the stored Exp7 runs, and a rerun of four arms on the same instance reproduced the stored values. Hypotheses and analysis were fixed before each check. Fact precision has a registered non-inferiority contrast (margin $-$5 points). On T-REx, the Exp7 arms have a registered equivalence test (margin $\pm$3 points); seeded extraction led the combined pipeline there, so the test did not establish equivalence. In Exp8, the hybrid-QA contrasts are registered and only the analysis of why hybrid QA fell is post hoc; KG-only QA and evidence recall are secondary measures.

\paragraph{Serving instances.}
The 60-fact hybrid run, the outside-shard list run and the EDC run with the list used another serving instance than the stored arms they are compared with; the instance changed during the hybrid and outside-shard runs and after the first 12 EDC units. The same arm differed between serving instances (no list .433 stored, .417 rerun), so contrasts are taken within one instance where possible. The retrieval comparison reran seeded extraction on the retrieval arms' own serving engine (.669 against .678 in the stored run). The selector arms of the equal-fact-count check ran on a different serving engine from the stored guided-pass arm. The reruns of the dose check (Table~\ref{tab:seeddose}) all come from one instance; the stored Exp7 values come from another.

\paragraph{List induction.}
For the induced list an LLM proposed relation names from 300 chunks of the corpus being built and the proposals were merged into 22 names. No question and no gold relation was used. On T-REx a list of 22 names was induced the same way from 300 of the 386 evaluation-corpus passages, again with no questions and no gold relations. The induction therefore read passages of the corpus that is later queried (a transductive setting), and 4 of its 22 names match the 2Wiki list exactly. The list induced outside the evaluation shards was built with the same procedure from 96 passages outside the evaluation shards, so no evaluation passage and no question was read; 15 of its 22 names match the first T-REx list and 6 match the 2Wiki list. It gave +7.4 points of grounded QA over no list in the single pass (Section~\ref{sec:res-schema}).

\paragraph{Statistics.}
Intervals resample 30 shards on 2Wiki (two run seeds averaged within a shard, 60 units) and 33 shards on T-REx per run seed. Intervals are two-sided 95\% unless marked one-sided or post hoc 90\%. P-values from 10,000 resamples have a floor of 1/10,001. Post hoc analyses reuse the stored predictions and make no new model calls.
